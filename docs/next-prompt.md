# Следующий промпт: поддержать `int?` в контрактах

Продолжай разработку Parenox. Начни с `AGENTS.md`, [справочника](reference.md)
и [замеров целочисленных контрактов](design/type-checker-research.md#checked-jvm-integer-conformer).
Сохрани текущие правки. Основная задача — статическая проверка обычного кода
на основе исходных spec и контрактов, а не новые возможности редактора.

## Задача

Закрой воспроизводимый пробел `Unsupported type int?` в
[`:error/code` из `lsp4clj` 2.0.1](https://github.com/clojure-lsp/lsp4clj/blob/1ff6c687f4e2af214d30df0d50749ea4a15b42c8/src/lsp4clj/coercer.clj#L17-L18):
`(s/and (s/or :kw keyword? :int int?) (s/conformer second))`.
Сначала повтори на JVM из `deps.edn` и сверь классы и результаты:

- `2147483648` — `Long`: проходит `int?`, хотя не помещается в Java `int`.
- `1N` и `(biginteger 1)` проходят `integer?`, но не `int?`, хотя оба значения помещаются в Java `int`.
- `:failed` проходит `:error/code` через ветку `keyword?`; строка и дробь не проходят.
- `(s/conform ::line 1N)` из предыдущего среза возвращает JVM `Integer`; это не тот класс, что у входного `1N`.

Добавь поддержку `int?` для исходных spec и проверяемых условий. Не своди
его к `Int32`, `integer?` или диапазону `long`: факт о классе и факт о
диапазоне независимы. Используй существующий reader и модель типов. Если
класс числа не доказан, оставляй проверку неполной. Не меняй семантику
`(s/and integer? (s/conformer int))` и не обобщай анализ произвольных
conformer. Не расширяй этот срез до map-as-function в `:file-event/type`.

## Проверка

1. До изменений сними `just pilot-check json` и отдельный прогон с настоящим
   `coercer.clj` v2.0.1 через `:dependency-sources`. Не правь закреплённые
   checkout. Сохрани диагностические коды, уровень и время.
2. Добавь тесты на реальное объявление `:error/code`: допустимые keyword и
   широкий `Long`, ошибки на небольшом BigInt и строке в типизированном
   вызове, а также неполную проверку для неизвестного класса. Проверь,
   что затенённый `int?` не даёт встроенного сужения и что тесты на прежнее
   преобразование в Java `int` по-прежнему проходят.
3. Выполни `just verify`, `just agent-loop` и оба прогона пилота.
   Отдельно покажи подтверждённые ошибки типов и оставшиеся пробелы.
   Результаты и границы запиши в `docs/design/type-checker-research.md`.

Статический анализ не выполняет код проекта, не вызывает spec и не
подключается к REPL. Не добавляй Python и не меняй CI. Не улучшай метрики
подавлением диагностик или подстановкой `any?`.
